# WAAN v2.2.0

## What changed

- Standardized user-facing branding to `WAAN` / `WAAN Relay` across UI, runtime copy, and docs.
- Fully adopted Tailwind token usage in core shell surfaces and added CI enforcement via `check:tailwind-adoption`.
- Hardened relay metadata persistence:
  - `appendMessage` now defaults to batched metadata persistence.
  - Added deferred flush retry/backoff plus `metadata:persist:error` signaling for durability visibility.
- Improved app-shell modularity by extracting assembly wiring into dedicated factories (`js/appShell/assemblyWiring.js`) with new contract coverage.
- Removed Shoelace migration monkey-patching of native DOM methods and switched to observer-driven sync behavior.
- Updated visual baselines after intentional UI/copy changes and revalidated accessibility + visual suites.
- Extended release smoke process with explicit excellence gates (performance, accessibility, visual regression, naming consistency).

## Why this release matters

- Better reliability under relay ingestion load with significantly reduced metadata write amplification.
- Cleaner architecture and stricter quality gates improve maintainability and release confidence.
- Branding and copy consistency reduce user confusion across product surfaces.

## Installation / upgrade notes

- No data migration is required.
- Re-run visual snapshots only for intentional UI/copy changes (`npm run test:visual:update`), then verify with `npm run test:visual`.
